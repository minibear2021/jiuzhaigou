## 表格约定

- **行程表**（5 列）：`区段 | 用时/分钟 | 方式 | 行程 | 备注`。原图的合并单元格已拆成逐行重复的"区段"列；没有区段的过渡行记为 `—`。
- **步行数据表**（6 列）：`区段 | 点位 | 路程（米） | 单程耗时（分钟） | 台阶 | 爬升（米）`。`/` 表示原图该项无数据，负数爬升表示以下降为主。
- **地图点位表**（5 列）：`点位 | 海拔（米） | 类型 | 所在沟 / 区域 | 备注`。
- 时间统一写作"分钟"（原图 `min`）和"小时"（原图 `h`），数值不变。

## 修订约定

1. 只修改 Markdown，原图作为转写依据保留，不要删除或覆盖。
2. 保持表格列数一致；缺数据写 `—`；Markdown 不支持合并单元格，合并格请拆成重复值。
3. 修改数字、地名、票价等信息时注明出处（如"据 2025 年景区公告"），便于回溯。
4. 原图本身存在疑似笔误之处已在各文件 `## 转写存疑` 留痕（如步行数据区段的"日喀则"、加强版"尻鱼"），修订时请一并处理。

## 版本管理建议

- 图片是二进制文件，`git diff` 不可读；建议以 Markdown 作为主版本，日常提交只涉及 `.md`。若不需要把原图纳入版本库，可在 `.gitignore` 中追加 `*.jpg`、`*.png`（原图仍保留在本地供对照）。
- 按主题分次提交（如"更新门票信息""补充观景台说明"），commit message 可用 `docs: ...` 前缀。
- 若目录尚未纳入 git，初始化后提交初始版本即可。
